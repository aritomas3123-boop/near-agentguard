Security boundary:

This is a read-only planning and evaluation interface. It does not create or approve transactions. Eligible proposals require a separate, explicit human action with an independently controlled testnet wallet. A Gemini model is not considered connected until the status above explicitly confirms it.

03 / ENGINEERING TRANSPARENCY

What the contract does and does not do

Enforced in the NEAR testnet contract

Per-action reservation cap, daily account budget cap, strict recipient allowlist, nonce replay prevention, authorized reviewer-only approval, and on-chain audit state.

Verified build

The Docker build runs 20 Rust unit tests before producing the WebAssembly binary. Render publishes the identical artifact for inspection.

Read build verification ↗

Still outside the scope

This is a proof of the decision and approval layer. It is not a production wallet, custody system, transfer engine or full third-party security audit. It does not transfer funds, manage real-money payments, or control an external agent's wallet.

Testnet only.

All NEAR used in the proof is faucet-funded test currency without monetary value. Successful approval means an auditable state change, not payment execution.
